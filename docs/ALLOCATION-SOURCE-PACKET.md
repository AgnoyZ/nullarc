# Source-only allocation diagnostic handoff

`tools/allocation_source_packet.py` prepares the committed in-tree source
needed by the reviewed build-37 kernel, standalone reader and CPU/fake-I/O
snapshot tests. It does not build or deliver the missing target binaries.
The [package review](ALLOCATION-PACKAGE-REVIEW.md) and
[execution plan](ALLOCATION-EXECUTION-PLAN.md) retain their unmet gates.

## Dependency and notice scope

The reader includes `PhxNativeABI.h`, `PhxAllocationDiagnostic.hpp` and,
transitively, `src/amd/phx_topology.h` and `PhxAllocationSnapshot.h`. It uses
the user-client type and the versioned selector-31 snapshot layout. The
diagnostic header also provides queue reason names. A single exported reader
`.cpp` is therefore insufficient. Its native recipe links host IOKit and
CoreFoundation frameworks; framework binaries and Apple SDKs are not exported.

The kernel recipe compiles `kmod_info.c` and `PhxBringup.cpp`, includes the
component headers, and links the pinned MacKernelSDK startup library and
compiler support library. The source packet includes the complete committed
`src/phxbringup` tree plus topology, not the accelerator or Metal plugin.
It records MacKernelSDK pin `3f750085caa17ec3a7880f11c11bf4f48cd6a164` but does
not supply external SDK sources or library archives. A later native delivery
still needs its own complete SDK/source/notice and build-provenance review.

Root `LICENSE`, all `LICENSES`, `THIRD_PARTY_NOTICES.md`, the existing
`KEXT-PROVENANCE.md` and both supplemental ABI notices accompany the source.
The reader/diagnostic SPDX identifiers retain MIT OR GPL-2.0-only; topology
retains MIT. NativeABI's BSD-3-Clause attribution and the pinned Cobalt64 MIT
notice are both preserved, including the discrepancy already documented in
the [kext provenance review](KEXT-PROVENANCE.md). This export makes no new
licence determination or publication grant. Root notices describe additional
project components; their presence does not mean those binaries are included.

## Export contract

From a clean `downstream/780m-tahoe` checkout, pass an exact full `--commit`
matching HEAD and a nonexistent `--out` directly under ignored `build/`.
The exported core source/test trees, dependency pin, notice trees and native
compile workflow must still match reviewed snapshot commit
`1c17a1712cb3a64db31148cb33d0c2c9741e7e5d`. There is no CLI override for that
review pin. A changed core requires renewed review before updating the tool.

The exporter uses fixed source paths and Git reads only. It refuses missing
source/notices, symlinks/non-regular Git entries, binary/non-UTF-8 content,
missing quoted includes, source-archive substitutions/omissions, a changed SDK
pin, dirty/changed source, unsafe output placement and existing output. It
never recursively copies a working directory, downloads dependencies or
executes source from the archive. Snapshot `.inc` fragments are the four
specific files generated by the retained CPU test runner, not omitted build
dependencies. System headers and framework availability remain external.

The new 0700 directory contains a source tarball, `source-manifest.json` and
`SHA256SUMS`, all 0600. The manifest records commit/tree, per-file Git blob,
mode, SHA-256 and size, external inputs and explicit execution limits. Every
archive member must match its committed blob, including executable modes;
Git `export-ignore` or `export-subst` cannot silently change the source set.
No host paths, timestamps, user identity or raw target evidence are added.
The input repository is not modified. Existing outputs are never overwritten.

Unit tests use temporary Git repositories and text-only fixtures. An actual
committed export must additionally be read back independently and its actual
source exercised with the CPU snapshot harness and fake reader I/O. Such tests
do not open a service, compile a kext, establish native linkability or validate
real concurrency. Source-byte hashes and a manifest cannot attest which source
produced any future native binary.

## Native delivery remains separate

The existing compile-only workflow is retained as source for the reviewed
native commands and SDK pin. It is not dispatched or changed by this tool.
No artifact upload or new delivery channel is added. The public two-kext/RADV
exceptions still do not cover the standalone reader.

Before Phase A, a separately reviewed native build and controlled handoff must
retain the exact kernel/reader bytes, commands, toolchain, architecture,
signatures and trusted build-origin evidence; verify corresponding notices and
sources; and complete the recovery and live-preflight gates. A source packet
alone cannot authorize a build, transfer, installation, load, passive read,
startup change, GPU attempt or reboot.
