- Added the checked boot stage runner `tools/phx_boot_gate.sh` (`docs/BOOT-GATE.md`), the control-flow change `BRINGUP-AUDIT.md` requires without the reference workflow's side effects. It runs an operator-supplied, bytewise-ordered stage directory with a per-stage timeout, stops at the first failure, and runs an operator-supplied release hook on every exit path after taking the lock, so a failed attempt cannot leave PhxAMDFB holding the GPU. A crash marker separates a handled failure (marker removed, exit 77/78) from a killed attempt (marker kept; the next run refuses with 76 and leaves the panel on the firmware framebuffer); a stale lock is replaced only when its recorded PID is gone. It never reboots, writes NVRAM, writes sysctl, kills by process name, installs anything, or embeds an address constant: the expected kext build is a required argument and only `uname` plus PhxBringup's published `phx-*` properties are read. It does not parameterise `mesboot.c`'s register sequence and ships no stages. POSIX shell tests exercise the real script with fake host commands (Linux CI; Windows only `sh -n` and a manual smoke). No macOS host or target machine has run it; it is not installed and adds no acceleration evidence.
